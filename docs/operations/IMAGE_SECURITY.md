# Безопасность выпускаемых образов

Статус остаточного риска приложения: **NOT_ACCEPTED / release blocker**.

Текущие версии образов, результаты inventory, fixable gate и границы проверки собраны
в [едином аудите](../AUDIT.md#остаточный-security-inventory-образов). Полные inventories
следует хранить в CI artifacts соответствующей сборки, а не в Git с историей аудитов.

PostgreSQL base, Redis и Mailpit закреплены digest и имеют отдельный CI scan job.
Само обновление тега или digest не подтверждает отсутствие уязвимостей; перед выпуском
нужен новый scan точных используемых образов.

## Оценка и решение

Предыдущий статический анализ прикладного Core/Commercial кода не нашёл прямых вызовов
DOMDocument, SimpleXML, XML parser или libxml. PHP-расширения присутствуют в образах.
Отсутствие прямого вызова не исключает достижимость через зависимости и не является
exploit PoC или основанием автоматически принять риск.

Владелец решения — security lead платформы. До выпуска требуется совместимое исправление
base image/package с regression evidence либо письменное принятие остаточного риска
с мерами ограничения, ответственным и датой пересмотра. Такое решение пока не получено.
Ограничение XML/content types и мониторинг можно рассматривать как меры до решения;
их наличие и эффективность должны быть подтверждены в конкретном развёртывании.

CI должен отдельно публиковать полный inventory HIGH/CRITICAL и результат fixable gate.
`ignore-unfixed` ограничивает gate исправляемыми находками; его PASS не означает
«уязвимостей нет». Не добавлять исключения CVE ради зелёного статуса.

Для воспроизведения использовать Trivy с точным image digest и зафиксировать версию
scanner, время обновления vulnerability DB и полный JSON как artifact проверки.
Общие условия выпуска: [READINESS](READINESS.md).
