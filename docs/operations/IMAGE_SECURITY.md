# Безопасность выпускаемых образов

Статус остаточного риска приложения: **NOT_ACCEPTED — не принят, препятствие выпуску**.

Версии образов, инвентари, проверка исправляемых уязвимостей и границы исследования находятся в [аудите](../AUDIT.md#остаточный-инвентарь-безопасности-образов). Полные отчёты хранятся в материалах соответствующей сборки CI, а не в истории аудитов Git.

Базовый образ PostgreSQL, Redis и Mailpit закреплены точными хешами и отдельно сканируются CI. Смена тега или хеша не доказывает отсутствие уязвимостей; перед выпуском сканируются точные используемые образы.

## Оценка и решение

Прежний статический анализ Core/Commercial не нашёл прямых вызовов DOMDocument, SimpleXML, XML-парсера или libxml. Расширения PHP при этом есть в образах. Отсутствие прямого вызова не исключает достижимость через зависимости, не является воспроизведением эксплуатации и не разрешает автоматически принять риск.

Решение принимает руководитель безопасности платформы. До выпуска нужны совместимое исправление базового образа/пакета с регрессионными доказательствами либо письменное принятие остаточного риска с ограничивающими мерами, ответственным и датой пересмотра. Такое решение пока отсутствует. Ограничение XML и типов содержимого, мониторинг допустимо рассматривать как временные меры, но их наличие и эффективность проверяются в конкретной установке.

CI отдельно публикует полный перечень уязвимостей высокой и критической опасности и результат проверки исправляемых находок. `ignore-unfixed` ограничивает проверку исправляемыми находками; её успех не означает отсутствия всех уязвимостей. Не добавляйте исключения CVE ради успешного статуса.

Для воспроизведения используйте Trivy с точным хешем образа, сохраните версию сканера, время обновления базы уязвимостей и полный JSON-отчёт. Общие условия: [готовность выпуска](READINESS.md).
