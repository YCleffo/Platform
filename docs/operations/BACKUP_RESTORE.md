# Резервирование и восстановление

Автоматическое локальное резервирование отключено. Основной Compose не запускает backup-worker, restore-drill или временные PostgreSQL. Резервирование промышленной установки должно быть настроено отдельно и проверено восстановлением до выпуска.

## Формат и проверка

Используйте PostgreSQL custom format (`pg_dump -Fc`). Проверяйте ненулевой размер, SHA-256 и `pg_restore --list`. Отсутствие ошибки при создании файла не подтверждает его восстановимость. Дамп содержит персональные данные, хеши паролей и зашифрованные факторы MFA; доступ и шифрование определяются политикой установки.

Инфраструктурная реализация `infra/backup` сохранена как отдельная возможность: она публикует manifest после успешной проверки дампа, проверяет размер и хеш и обрабатывает checkpoint перед обновлением или удалением выделенной установки. В текущем локальном окружении этот worker не включён. Provisioning, требующий такого checkpoint, должен оставаться остановленным до настройки резервирования.

## Восстановление рабочей базы

`scripts/restore-db.ps1` требует конкретный путь и явное указание целевой базы. До запуска остановите HTTP и все фоновые процессы соответствующего приложения. Для production требуется дополнительный параметр `-ConfirmProductionRestore`.

```powershell
./scripts/restore-db.ps1 -Target Core -DumpPath C:/secure/core.dump -Force -AllowLiveRestore
./scripts/restore-db.ps1 -Target Control -DumpPath C:/secure/commercial.dump -Force -AllowLiveRestore -ConfirmProductionRestore
```

Это замена данных указанной базы. После восстановления сверяются история миграций, ограничения, финансовые снимки и privacy erasure; HTTP и workers запускаются после этой проверки. Миграции применяются [отдельной операцией](SAFE_DATABASE_UPGRADE.md).

Локальные дампы и runtime-артефакты исключены из Git и проектного ZIP. Политика удаления копий должна учитывать retention и legal holds; удаление копии само по себе не является уничтожением персональных данных во всех системах.
