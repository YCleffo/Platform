# Резервирование и восстановление

Автоматическое локальное резервирование отключено. Основной Compose не запускает обработчик копий, учение восстановления или временные PostgreSQL. Резервирование промышленной установки должно быть настроено отдельно и проверено восстановлением до выпуска.

## Формат и проверка

Используйте специальный формат PostgreSQL (`pg_dump -Fc`). Проверяйте ненулевой размер, SHA-256 и `pg_restore --list`. Отсутствие ошибки при создании файла не подтверждает его восстановимость. Дамп содержит персональные данные, хеши паролей и зашифрованные факторы MFA; доступ и шифрование определяются политикой установки.

Инфраструктурная реализация `infra/backup` сохранена как отдельная возможность: она публикует манифест после успешной проверки дампа, проверяет размер и хеш и обрабатывает контрольную резервную копию перед обновлением или удалением выделенной установки. В текущем локальном окружении этот обработчик не включён. Подготовка установки, требующая такой копии, должен оставаться остановленным до настройки резервирования.

## Восстановление рабочей базы

`scripts/restore-db.ps1` требует конкретный путь и явное указание целевой базы. До запуска остановите HTTP и все фоновые процессы соответствующего приложения. Для промышленной среды требуется дополнительный параметр `-ConfirmProductionRestore`.

```powershell
./scripts/restore-db.ps1 -Target Core -DumpPath C:/secure/core.dump -Force -AllowLiveRestore
./scripts/restore-db.ps1 -Target Control -DumpPath C:/secure/commercial.dump -Force -AllowLiveRestore -ConfirmProductionRestore
```

Это замена данных указанной базы. После восстановления сверяются история миграций, ограничения, финансовые снимки и уничтожение персональных данных; HTTP и фоновые обработчики запускаются после этой проверки. Миграции применяются [отдельной операцией](SAFE_DATABASE_UPGRADE.md).

Локальные дампы и материалы рабочей среды исключены из Git и проектного ZIP. Политика удаления копий должна учитывать сроки хранения и юридические запреты уничтожения; удаление копии само по себе не является уничтожением персональных данных во всех системах.

## Следующие шаги для промышленной эксплуатации и роста

1. Утвердить RPO/RTO, расписание, сроки хранения, шифрование и доступ; подключить отдельный
   обработчик копий или внешний механизм резервирования и восстановления на момент времени PITR. Основной Compose их не запускает.
2. Для включённого Education сохранять байты закрытых файлов вместе с согласованным
   состоянием БД; `pg_dump` содержит только метаданные файлов. Проверить восстановление скачивания с совпадающими SHA-256 и размером и действующей авторизацией.
3. Выполнить учение восстановления, включая PITR, сверку финансовых снимков и повтор уничтожений
   после даты копии до возврата трафика; проверить доставку оповещения при отказе резервирования.

Это открытые работы, а не подтверждённая возможность текущей установки.

## S3 object backups (STORAGE_02)

The current executable PostgreSQL + S3 encrypted snapshot and restore procedure is documented in [STORAGE_02](STORAGE_02.md). A database-only dump does not back up object bytes. The local restore exercise passed with seven objects on 2026-11-15; external offsite scheduling remains an installation requirement.
