# Административная консоль Core

Консоль находится в общей одностраничной SPA по `/admin`, но использует **отдельную сессию Core и модель разрешений**. Клиентские учётные данные и токены не переиспользуются. Токены хранятся только в памяти; после полной перезагрузки нужен новый вход.

## Локальный вход

Один раз создайте первого супер-администратора Core:

```bash
docker exec -e CORE_BOOTSTRAP_PASSWORD='<strong-local-password>' \
  platform-backend-1 php yii core:bootstrap-superadmin \
  --email=admin@platform.local --given-name=Platform --family-name=Admin \
  --locale=ru-RU --timezone=UTC
```

При работающем сервере разработки Vite откройте [страницу входа](http://localhost:5173/admin/login). В описанной локальной установке используются `admin@platform.local` и пароль, переданный команде начальной настройки.

## Страницы

- Обзор: текущие счётчики из административных API Core и распределение статусов аккаунтов.
- Организации: список, создание, список участников, добавление и удаление.
- Люди: список, создание, изменение, архивирование и контакты.
- Аккаунты: список, создание, жизненный цикл, приглашения и сервисные учётные данные.
- RBAC: роли, разрешения, замена набора разрешений роли и назначение ролей аккаунту.
- Модули: жизненный цикл и настройки модулей.
- Настройки: системные значения и флаги возможностей.
- Персональные данные: запросы субъектов, запреты уничтожения, уничтожение, инциденты, представительство и согласия на распространение.
- Аудит: журнал Core, доступный только супер-администратору.
- Финансовые компенсации: переход в `/operator`, где нужны независимая сессия оператора Commercial и действующая серверная авторизация. Клиентская сессия и сессия Core не используются.

Действия справочников и персональных данных используют явные схемы полей, выбор сущностей, списки кодов, переключатели, действия с учётом статуса и подтверждения. Формы изменения загружают существующие значения; замена разрешений роли читает текущий набор. Редакторы произвольного JSON и неиспользуемые универсальные панели удалены. `npm run test:workbench-contracts` сверяет требования серверных маршрутов с каталогом интерфейса.

Результаты открываются полноэкранными диалогами; секреты сервисных учётных данных очищаются при закрытии. Все списки и действия вызывают реальные `/api/core/*`; интерфейс не выдумывает записи.

## Локальная производительность

Консоль обращается к Core через сервис Compose `backend-fast` на `127.0.0.1:8082`. Он использует промышленную цель сборки с включённым в образ кодом и без отладочного Xdebug, подключаясь к тем же PostgreSQL и Redis. Обычный `backend` остаётся для автоматической подгрузки изменений, фоновых процессов и отладки.

Vite читает исключённый из Git `apps/frontend/.env.local` и направляет `/api` на 8082. После изменения серверного кода пересоберите и перезапустите быстрый сервис:

```bash
docker compose up -d --build --no-deps backend-fast
```

Прежние локальные измерения дали примерно 45–60 мс против 1–3 с в отладочной среде. Это исторические измерения, а не текущая оценка предельной нагрузки. Обзор и предварительная загрузка навигации используют кэш с областью сессии Core. Таблицы рабочих справочников читают свежие страницы и держат строки только в пределах компонента и сессии. Отказ в разрешении очищает строки и итоги пагинации; поздний ответ не заполняет новую сессию.

## Поведение таблиц и навигации

- Для каждого постраничного ресурса внизу таблицы есть выбор размера страницы 10/25/50/100 через общий `AppDropdown`. Изменение сбрасывает смещение и загружает новую страницу. Поле компактное: высота 32 пикселя, ширина 96; пункты меню — 30 пикселей, текст 12, отступы 4/8. Панель не уже 96 пикселей, совпадает с шириной кнопки, открывается снизу и ограничивается экраном.
- Заголовки таблиц закреплены сразу под непрозрачной верхней панелью, со смещением 68 пикселей. На широком экране обёртки AppCard и таблиц не создают отдельную вертикальную прокрутку: прокручивается страница, строки не видны сквозь зазор.
- Ширину раскрытой боковой панели можно менять за правый край в пределах 200–340 пикселей; значение сохраняется. Перетаскивание ниже 200 сворачивает её до 68 пикселей; движение из свёрнутой панели раскрывает её. Отпускание вне окна или отмена указателя возвращают ширину до начала перетаскивания. Разделитель доступен с клавиатуры через стрелки влево и вправо.
- При сворачивании текущая ширина анимируется до 68 пикселей, равных высоте верхней панели. Подписи обрезаются с `nowrap`, а не переносятся; логотип остаётся на той же горизонтальной позиции, кнопка сворачивания размещена абсолютно рядом. Промежутки пунктов и разделов уменьшаются до 4/0 пикселей.
- Истёкшая или отозванная сессия немедленно переводит на `/admin/login?redirect=…`, не оставляя старую страницу с сообщением об ошибке.
- Внутреннего отступа карточки таблицы нет: закреплённые верх и низ прилегают к краям. Нижняя панель имеет симметричный отступ 8 пикселей; действия строки собраны в компактном выпадающем меню.
- На широком экране таблицы имеют фиксированную раскладку: раскрытие боковой панели не вызывает горизонтальную прокрутку страницы. Горизонтальная прокрутка обёртки появляется только ниже 1200 пикселей. Меню действий сохраняет строки короткими.
- Фирменный знак центрирован по вертикали в верхней строке 68 пикселей. Подписи навигации занимают оставшуюся ширину и обрезаются многоточием; свёрнутые значки размером 18 пикселей центрированы.
- Наведение подсвечивает строку и столбец бледными акцентами: 6%/4%, ячейку под указателем — 9%. Заголовок столбца подсвечивается поверх карточки.
- Отступы ячеек 8/12 пикселей совпадают с кнопками; заголовки закреплены под верхней панелью. Подписи, кнопки и меню запрещают выделение текста через `user-select: none`; поля ввода, многострочный ввод, предварительно форматированный текст и код остаются выделяемыми.
- В свёрнутом виде каждый пункт использует общий `AppTooltip`. Доступное имя ссылки сохраняется через `aria-label`; подсказка служит только зрительным дополнением.
- На страницах аутентификации нет отдельной ссылки на настройки. Административный вход использует собственные аккаунт и сессию Core.
