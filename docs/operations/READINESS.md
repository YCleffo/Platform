# Условия выпуска Platform

Текущий статус: **NOT_READY**. Результаты последней локальной проверки и конкретные
дефекты находятся в [актуальном аудите](../AUDIT.md). Эта страница содержит условия
выпуска, а не историю прогонов. Локальная проверка не заменяет запуск GitHub Actions.

До production необходимо:

1. Получить полный зелёный CI для выпускаемого SHA: Core, Commercial, cross-plane,
   документация, браузерные сценарии и сканирование образов. Изоляция browser fixtures
   уже настроена в workflow; её необходимо подтвердить новым полным запуском.
2. Проверить runtime-роли HTTP/workers в выпускаемом окружении: бизнес-операции и отказ
   запрещённых действий именно по правам доступа, включая SQLSTATE.
   [Инструкция по ролям](DATABASE_ROLES.md).
3. Получить свежий inventory для точных digest всех выпускаемых образов и закрыть
   исправляемые HIGH/CRITICAL. Остаточный риск приложения пока **не принят**:
   [решение по образам](IMAGE_SECURITY.md).
4. Проверить реальные SMTP и платёжный provider/YooKassa, TLS/DNS, секреты и ingress.
   Работа с Mailpit и fake provider в тестах не подтверждает внешнюю интеграцию.
5. Выполнить restore/PITR drill, подтвердить мониторинг, фоновые workers и восстановление
   после перезапуска. [Резервное копирование](BACKUP_RESTORE.md),
   [безопасное обновление БД](SAFE_DATABASE_UPGRADE.md).
6. Утвердить production privacy-конфигурацию и документы развёртывания;
   провести нагрузочную приёмку с реальными объёмами данных и согласованным SLO.

Локальный Compose использует dev-модель. Однопользовательский нагрузочный smoke,
автоматический axe и наличие backend endpoints не являются доказательством production
capacity, полного соответствия WCAG или завершённости всех пользовательских экранов.
Граница Commercial и будущего Education определена в [roadmap](../roadmap/PLATFORM_ROADMAP.md).
