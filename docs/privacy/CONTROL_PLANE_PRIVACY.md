# Граница персональных данных Control Plane

`ControlPlane/Privacy` работает непосредственно с БД Commercial и не зависит от БД Yii Core. Коммерческий аккаунт — организационная и расчётная область, а не субъект персональных данных. Субъектом может быть Control User, контактное лицо плательщика или другой человек в неизменяемом финансовом снимке. Собственная выгрузка разрешается по ID Control User; она не выгружает данные всех людей коммерческого аккаунта.

| Хранилище | Персональные данные | Выгрузка и хранение |
| --- | --- | --- |
| `control_users` | Почта, статус, времена идентичности, хеш пароля | Только безопасные поля личности; хеш не выгружается. Псевдонимизация требует утверждённой политики и отсутствия финансовой связи |
| `control_sessions`, история обновления | Хеши токенов и IP, User-Agent, времена безопасности | Только безопасные статусы и времена. Истёкшие сессии и связанная история очищаются порциями после утверждённого срока и проверки запретов уничтожения |
| Подтверждения почты | Хеш токена и срок | Хеш не выгружается. Очистка после истечения и дополнительного утверждённого срока |
| `commercial_account_memberships` | Связь пользователя и аккаунта, роль | Только собственные членства. Единственный активный владелец блокирует уничтожение до передачи владения |
| `billing_profiles` | Контактное имя/почта, юрлицо, налоговые и адресные поля | Контакты выгружаются при совпадении почты субъекта. Уничтожение очищает совпавшие изменяемые контакты, сохраняя деловой профиль |
| `invoices`, `receipts` | Неизменяемые контактные снимки счета и чека | Только совпавшие с субъектом контактные поля. Финансовые документы сохраняются; срок не придумывается |
| Платёжные и фискальные записи | Ссылки провайдера, суммы, доказательства платежа и фискализации | Требуется финансовая политика хранения. Уничтожение пользователя эти записи не удаляет |
| `audit_events` | ID исполнителя/ресурса, ограниченные разрешённые метаданные | Обычным путём только добавление; контролируемая очистка по срокам и запретам уничтожения |
| `outbox_events` | ID подтверждения и метаданные доставки | Новые события хранят только ID; получатель читается из Control User перед отправкой. Миграция 021 удаляет прежних получателей из очереди и очищает опубликованные почтовые данные. Очистка завершённых и необрабатываемых событий ограничена политикой |
| Идемпотентность и ограничение частоты | Хеш запроса или сетевых признаков | Хеши не входят в собственную выгрузку. Утверждённые сроки и ограниченная очистка |

`ControlPersonalDataExporter` объединяет типизированных поставщиков сведений личности, безопасности и Commercial, фиксирует событие выгрузки без тела ответа. `ControlUserErasure` выключен до утверждения политики установки. При включении он проверяет активный запрет уничтожения и единоличное владение, удаляет данные безопасности, отзывает членства, очищает совпавшие изменяемые контакты и отключает учётные данные.

При финансовой истории связанного аккаунта связь личности сохраняется с результатом `partially_completed`; без неё почта заменяется устойчивым псевдонимом. Псевдонимизация не равна анонимности: ссылки в делах, аудите и других записях могут остаться.

`control:security:cleanup` по умолчанию работает без удаления, принимает категорию и ограниченный размер порции, выводит только счётчики. `control_privacy_retention_days` содержит проверенные положительные сроки; неизвестная категория блокирует действие. Настройка жизненного цикла БД сама не разделяет роли. Промышленная установка должна ограничить команду ролью оператора/БД и защитить копии и повторное уничтожение после восстановления.

Аутентифицированная собственная выгрузка: `GET /api/control/privacy/me/export`, ответ `no-store`. Утверждённое уничтожение запускает привилегированный оператор через `control:privacy:erase`. До флага политики и явных сроков идентичности/контактов оно заблокировано. Ноль дней означает утверждённое удаление по событию; положительный срок требует ранее установленной даты `archived_at`, от которой он уже прошёл.

Установка отдельно задаёт `control_privacy_processing_roles` для целей оператора или обработки по поручению и сохраняет внешние ссылки на поручения/договоры. Провайдеры, прежде всего YooKassa и SMTP, требуют утверждённого инвентаря получателей и передач. Конкретные шлюзы почты, платежей, возвратов и чеков проверяют цель, категории, страну, ссылку на доказательство и статус уведомления о зарубежной передаче перед исходящим запросом.

`control:privacy:check` — проверка только чтения; неполные сроки, роли, решения провайдеров, резидентность и сведения безопасности дают отказ. Этот технический инвентарь не устанавливает юридический срок и не удостоверяет соответствие требованиям.

## Приглашения

`commercial.commercial_account_invitations` содержит нормализованную почту получателя, роль, отправителя, статус и срок. Открытый токен не хранится. Выгрузка субъекта включает приглашения, где он отправитель, принявший или приглашённый. Уничтожение отзывает ожидающие приглашения на его адрес и псевдонимизирует почту.

Категория хранения `invitation` задаётся через `CONTROL_PRIVACY_RETENTION_DAYS`; без значения очистка и проверка готовности не проходят. Исходящая почта приглашений требует отдельно утверждённых цели и категорий; автоматического одобрения нет.
