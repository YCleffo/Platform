## Оставшиеся дефекты

1. **P1: Storage не проходит основной сценарий записи.** `PostgresStorageStore.php:150–151,359` использует `CASE WHEN :parameter IS NULL` для nullable UUID. PostgreSQL возвращает `SQLSTATE 42P08` — неизвестен тип параметра. Это воспроизводят четыре Storage-теста, включая загрузку/скачивание и манифест агента. Следующий шаг: типизировать nullable параметры, повторить Foundation и добавить HTTP-проверку передачи файла.
2. **P1: HTTP-диспетчер Storage содержит отдельные ошибки исполнения.** В `StorageAction.php:40` любая DeviceIdentity сначала попадает в match без upload/download; эти агентские операции завершаются `not_found` до обработчиков передачи файла. В строке 78 создаётся отсутствующий `Yiisoft\Http\Response`; Psalm подтверждает `UndefinedClass`. Нужны проверки реальных HTTP upload/download, поскольку сервисные тесты этот путь не покрывают.
3. **P1: контракт жизненного цикла DeviceManagement расходится с тестами.** Падают `testSessionLifecycleTransitionsAndSingleActiveSessionInvariant` и `testSyncPendingBlocksNextSessionAndRevokedDeviceStops`: повторная выдача доставленной команды и отклонённый переход. Следует согласовать правила повторной доставки/подтверждения и восстановления с агентом; нельзя считать этот модуль принятым по зелёным старым задачам CI.
4. **P2: неверная проверка UUID.** `DeviceAccess.php:39`: `!preg_match(...) === 1` сравнивает bool с int и всегда ложно. Это не доказательство обхода авторизации: следующая проверка членства остаётся. Но формат идентификатора не проверяется в заявленном месте.
5. **P2: статический контракт новых модулей не доведён.** 84 ошибки Psalm включают неточные типы SQL-результатов/параметров, mixed-значения, nullable данные и ошибки исполнения выше. Снижение уровня анализа или baseline для скрытия ошибок не добавлялись.
6. **P2: payload-контракты Storage требуют сверки.** Например, OpenAPI `AgentTicketRequest` требует `spaceId`, а `StorageService::agentTicket()` разрешает другой набор полей и требует ожидаемые hash/size. Зелёная проверка маршрутов не доказывает совместимость тел запросов.
7. **Рабочие PostgreSQL ещё используют старый образ.** В работающем `platform-postgres` подтверждён `zlib1g` версии `1:1.3.dfsg+really1.3.1-1+b1`. Исправление собрано и проверено в новом образе; его применение рабочим БД требует отдельного планового пересоздания контейнеров с сохранением томов и резервной копией.

- Проверочные контейнеры Prometheus/Alertmanager запускаются с UID/GID владельца временных файлов.

- Добавлен недостающий GET manifest в Storage OpenAPI и таблицу соответствия operationId.
- Исправлены CSS-токены Education, мигание каретки учитывает настройки движения; Vue-файлы отформатированы.
- Браузерные проверки используют существующий default preset, фактический брейкпоинт 768, относительное увеличение switch thumb и зарегистрированные маршруты Vue Router с поддержкой необязательных параметров.
- Перегенерированы два файла покрытия БД.
- PostgreSQL собирается с исправленным zlib; локальный Trivy и существующий gate подтверждают **0 исправляемых HIGH/CRITICAL**. Остаются **64 HIGH и 1 CRITICAL без выпущенного исправления**; полный перечень не скрывался.

Остальные скрипты сверены с прямыми ссылками, импортами и автопоиском тестов; отсутствие буквального имени не использовалось как основание для удаления.
