## Classroom

На `classroom02_test` исходный код воспроизвёл две ошибки, 2 теста и 2 падения.

| Регрессия | Первопричина | Исправление |
| --- | --- | --- |
| `testNativeActiveAndStorageCleanupNeedIndependentConfirmations` | Проверка Storage была условной и пропускалась при отсутствии Storage space. Раннее подтверждение синхронизации могло учитываться при cleanup. | Требуется серверный checkpoint для этого устройства и ученика после начала `SYNCING_OUT`. Для пустого пространства Agent явно отправляет пустой проверяемый снимок. |
| `testRecoveryCanEndPreparedSessionWithoutFalselyConfirmingWindowsLogon` | `APP_ENV=test` пропускал проверку запроса завершения и позволял переходы без обязательного evidence. | `ENDING` и `SYNCING_OUT` требуют запроса завершения. Recovery выходит из подготовленной сессии без записи подтверждённого Windows logon. |

Production принимает `ACTIVE` после подтверждения подготовки профиля и `windowsLogonConfirmed` от зарегистрированного Agent. `testAdapter` разрешается отдельной DI-конфигурацией для проверенного изолированного runtime. Отчёт, содержащий одновременно synthetic и Windows evidence, отклоняется. Cleanup блокируется при отсутствии требуемого checkpoint, наличии ожидающего манифеста или более свежего манифеста, требующего восстановления. Повторная доставка команды и повторный отчёт `CLOSED` сохраняют одну сессию. [Проверки состояния](../../apps/backend/tests/Classroom/ClassroomPostgresRegressionTest.php)

Панель устройств использует действия и подтверждения от backend. Добавлен браузерный сценарий назначения, завершения, сбоя при сохранении, блокировки следующего назначения, повтора восстановления, повторной доставки, чтения байтов из SeaweedFS и журнала. Синтетический Agent использует действующую схему регистрации и HTTP API. [Браузерный сценарий](../../apps/frontend/scripts/e2e-education-classroom.mjs)

## Преподаватель и ученик

Сценарий преподавателя проходит через создание записи человека и Student, выбор существующего человека, создание и завершение занятия, посещаемость, результат с комментарием, карточку и журнал. В сценарии предусмотрены проверка хранения, отсутствие побочного создания учётной записи и отказы за границей доступа. [Браузерный сценарий](../../apps/frontend/scripts/e2e-education-teacher.mjs)

Исходный Education browser regression также прошёл с реальным backend, включая делегирование группы, перенос занятия, файл с проверкой байтов, журнал, архив и обмен сообщениями. Родительский тест проверяет сверку доступа как при автоматическом обновлении контекста, так и после ручного обновления. Storage-тест сохраняет входы, необходимые для проверки logout и reload, в пределах существующего лимита Core. [Ролевые сценарии](../../apps/frontend/scripts/e2e-education-roles.mjs)

Для ученика добавлены отмена скачивания с проверяемыми байтами, повтор загрузки исходного файла, сверка серверного результата при потерянном ответе `complete` и явное повторное подтверждение после конфликта версии. Первая проверка перезагрузки обнаружила, что прежний резерв блокировал повторный выбор того же файла. Core теперь возобновляет существующую передачу при совпадении владельца, пространства, пути, размера, SHA-256 и исходной версии. Скачивания до 64 МиБ проверяют размер и SHA-256 перед передачей браузеру. Более крупные файлы передаются менеджеру скачиваний браузера, где можно управлять передачей. [Хранилище ученика](../../apps/frontend/src/modules/education/student/StudentDocumentsView.vue) · [Восстановление передачи](../../apps/backend/src/Storage/Infrastructure/StorageTransferService.php)

| L | Устаревшая запись после восстановления | Пройдено. В истории нет версии из устаревшей передачи, восстановленные байты сохранены. |
