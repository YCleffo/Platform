# Пользовательские настройки и приватность Core

## Граница ответственности

`Core/AccountSettings` владеет хранением, версионированными значениями по умолчанию, проверкой разрешённых полей, глубоким слиянием PATCH, авторизацией пользователя, конкурентной записью и аудитом. Доменные модули могут трактовать зарегистрированные значения, но не получают произвольного пространства JSON и не хранят здесь состояние аутентификации, RBAC, сессий или безопасности.

`locale` и `timezone` остаются в `core.accounts` и изменяются через `PATCH /api/auth/me/preferences`, чтобы не создавать второй источник истины.

## Хранение и версия

В `core.account_settings` максимум одна строка на Account. `settings` хранит только разреженный документ пользовательских переопределений. Отсутствие строки означает значения по умолчанию; GET её не создаёт. Текущая прикладная версия — `schema_version = 2`.

`SettingsSchemaRegistry::upgradeStored()` удаляет старые переопределения Education из версии 1, сохраняя общие предпочтения. Неизвестные будущие версии отклоняются.

PATCH глубоко объединяет данные, сохраняя соседние ключи. `null` допустим только в зарегистрированном конечном поле и удаляет переопределение, возвращая версионированное значение по умолчанию. Пустой результат удаляет строку. Явно переданное значение, даже равное значению по умолчанию, сохраняется как пользовательский выбор.

## Реестр Core, версия 2

| Путь | Тип | По умолчанию |
| --- | --- | --- |
| `interface.animations` | Логический | `true` |
| `interface.transparency` | Логический | `true` |
| `notifications.browser` | Логический | `true` |
| `notifications.sound` | Логический | `true` |
| `notifications.email` | Логический | `false` |
| `privacy.show_online_status` | Логический | `false` |

Реестр также поддерживает перечисления, диапазоны целых чисел и ограниченные типизированные конечные списки для безопасного расширения модулями. Они передают `AccountSettingDefinition[]` через параметр внедрения зависимостей `accountSettingsDefinitions`. Education сможет зарегистрировать пути `education.privacy.*`, но Core не знает их заранее.

## API

- `GET /api/auth/me/settings` возвращает `{settings, schema_version}` с вычисленными значениями по умолчанию и пользовательскими изменениями.
- `PATCH /api/auth/me/settings` принимает непустой JSON-объект до 32768 байт и возвращает тот же эффективный контракт.
- Оба маршрута требуют аутентификацию и берут аккаунт из текущего субъекта безопасности. Чужой Account не принимается ни в пути, ни в теле.

Неизвестные пространства и пути, неверные типы, массивы вместо объектов, ключи, связанные с прототипом, чрезмерная вложенность и будущие версии отклоняются. Секретных пространств и настроек безопасности в реестре нет.

## Конкурентная запись и аудит

Транзакция сначала блокирует `core.accounts` через `FOR UPDATE`, читает текущие переопределения, объединяет данные и выполняет UPSERT/DELETE. Та же блокировка сериализует первое создание, поэтому два PATCH разных полей не теряют изменения друг друга.

Изменение записывает `core.account_settings.updated` в общей транзакции. Аудит содержит только разрешённые изменённые пути и их пользовательские значения до/после; полный документ и посторонние данные не копируются. Повтор без изменения переопределения не создаёт события аудита.

## Что не входит в контур

Интерфейс, конкретные юридические документы, бизнес-логика модулей и отдельный административный API не входят в ответственность этого слоя. Постоянные согласия, правила уведомлений и временное присутствие описаны в [персональных данных Core](PRIVACY_COMPLIANCE_CORE.md), [уведомлениях](NOTIFICATIONS.md) и [присутствии](PRESENCE.md).
