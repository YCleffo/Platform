# Education: серверная часть и установка

Принят отдельный Yii-модуль `App\Education` со схемой PostgreSQL `education` и учётными записями Core. Условия старта выполнены до реализации: [полный CI #22](https://github.com/YCleffo/Platform/actions/runs/42081869693) для `ea0dc55425395f11fe56c6c2e16b9a9cb8a83445` прошёл 13 задач. Результаты самой реализации фиксируются отдельно в [аудите](../AUDIT.md).

## Границы и владельцы

Core владеет Account, Person, Organization, членствами, RBAC и аутентификацией. Education использует их публичные прикладные интерфейсы. Предметная область Core не зависит от Education; подключение выполняет корневая сборка зависимостей. Commercial не содержит учебных таблиц и не предоставляет учётные записи Education.

Первый рабочий сценарий — преподаватель. Каждый запрос требует активную учётную запись Core, актуальное разрешение, активное членство в выбранной организации и явное назначение преподавателя Education. Членство и супер-администратор сами по себе не заменяют доменную связь. Группы, ученики, занятия и материалы ограничены организацией и владельцем; диалог доступен только участникам. Адресаты первой версии — назначенные преподаватели той же организации.

| Данные | Владелец и поведение |
| --- | --- |
| Учебный профиль | Education; собственное имя, иначе имя Core Person; аватар необязателен |
| Группы и ученики | Education; ученик выбирается из активного списка людей организации Core |
| Занятия и посещаемость | Education; участники фиксируются при создании, новые зачисления добавляются в будущие занятия |
| Расписание и хронология | Проекции реальных занятий и событий, сортировка по моменту времени и ID |
| Требует внимания | Занятия предыдущего локального дня с сохранёнными отсутствиями; пустой список скрывает блок |
| Переписка и уведомления | Education; сообщения двух преподавателей, входящие сообщения и возрастающий указатель прочтения |
| Материалы и аватар | Education; метаданные в БД, закрытый файловый адаптер вне корня веб-сервера |

Отсутствие организаций, занятий, материалов и событий имеет своё пустое состояние. Ошибки не превращаются в успешный пустой ответ. Рабочая среда не создаёт демонстрационных данных. Тестовые учётные записи и списки Core создаются только после проверки одноразового окружения.

## HTTP и интерфейс

[Контракт OpenAPI Education](../../contracts/openapi/education.yaml) содержит 33 операции. Организация передаётся в `X-Education-Organization`; сервер повторно проверяет доступ. Все личные ответы, включая ошибки авторизации, имеют `Cache-Control: no-store`. Страница коллекции — до 50 записей, диапазон расписания — до 31 локального дня. Границы дня учитывают часовой пояс IANA и переходы летнего времени DST.

Интерфейс включает `/today`, `/calendar`, `/people`, `/messages`, `/more`, формы создания, детали занятий, посещаемость, материалы и уведомления. Шесть быстрых действий ведут в реальные сценарии. `/lessons/current` явно сообщает об отсутствии текущего занятия. Неделя, выбранная дата и язык берутся из контекста сервера. Нижняя навигация имеет пять пунктов, высоту 72 пикселя плюс безопасную область экрана. Inter хранится локально. Канонический светлый экран: [мобильный макет](../../apps/frontend/design/мобайл.svg), 393×852.

Материалы: PDF, `text/plain`, PNG, JPEG, WebP, до 10 МиБ. Аватар: только изображения до 2 МиБ и 20 млн пикселей. MIME определяется содержимым. Выдача заново проверяет разрешение, длину и SHA-256. Имя не задаёт путь хранения. Адаптер заменяется через `FileStore`; нескольким репликам нужно общее постоянное хранилище.

История по умолчанию возвращает последнюю страницу сообщений по возрастанию времени. Прочтение передаёт ID последнего действительно показанного сообщения, не отмечая пришедшие позднее. Список обновляется явным действием. При смене пользователя или организации запросы отменяются, интерфейс очищается. Секреты Core находятся в памяти; неопределённый результат записи требует сверки списка перед повтором.

## Установка без автоматической выдачи доступа

По умолчанию `EDUCATION_ENABLED=0`, `VITE_EDUCATION_ENABLED=0`: HTTP-маршруты и страницы отсутствуют. Принятие архитектуры само модуль не включает.

1. Применить обычные миграции Core отдельным подключением владельца. Затем выполнить `php yii education:migrate` тем же подключением миграций. Команда идемпотентна, проверяет SHA-256 применённых файлов и регистрирует выключенный модуль.
2. Повторить [выдачу ролей БД](../../scripts/operations/provision-db-role.sh) с `SCHEMAS=core,platform_runtime,public,education` и прежними раздельными секретами владельца, прикладной и служебной ролей. `education.module_migrations` доступен прикладной роли только для чтения. HTTP не работает от владельца БД.
3. Задать `EDUCATION_ENABLED=1` в Yii, выполнить `composer yii-config-rebuild` и перезапустить среду. Настроить постоянный `EDUCATION_FILE_DIRECTORY` вне корня веб-сервера с записью только для приложения. Общий файл `php.ini` разрешает загрузку 10M и POST 12M; обратный прокси должен допускать тот же размер.
4. Через администрацию Core включить `education`, назначить конкретному Account роль `education.teacher`. Нужны активный Person и членство требуемой организации.
5. Отдельно выполнить `php yii education:teacher:assign --actor <admin-account-uuid> --account <teacher-account-uuid> --organization <organization-uuid>`. Проверяются действующий администратор с `core.rbac.manage` и целевой участник. Массового назначения существующим пользователям нет.
6. Собрать интерфейс с `VITE_EDUCATION_ENABLED=1`, разместить с работающим прокси Core API и открыть `/education/login`. Корневой каталог Commercial `/` сохранён.

Выключение модуля Core немедленно блокирует API. Для полного удаления маршрутов выключить оба флага окружения и пересобрать/перезапустить соответствующие части.

## Проверки и границы выпуска

`tests/Education` запускается отдельно через PHPUnit с `EDUCATION_ENABLED=1` на защищённой одноразовой БД. Проверяются область доступа, актуальные разрешения, выключенный модуль, DST, хронология и пустой день, реальные файлы, указатель переписки, выгрузка и исправление. `scripts/e2e-education.mjs` проходит реальные вход Core, PostgreSQL и файлы, формы, завершённое скачивание, двух пользователей, русский/английский языки, светлую/тёмную темы, 393×852/1440 и axe. CI выполняет это после существующих браузерных сценариев Core.

Выгрузка, исправление, кандидаты хранения, основания помимо согласия, ограничения по цели и уничтожение подключены через интерфейсы Core. `education.workspace` представляет принадлежащую субъекту рабочую область. Обработчик уничтожения удаляет метаданные и внешние байты в порядке внешних ключей; `education.privacy_receipts(item_id, result)` записывается последним, делая повтор по ID элемента идемпотентным. Юридические запреты и основные блокировки Core остаются определяющими.

Синтетические тесты проверяют кандидатов, основания, ограничения, уничтожение и файлы. Промышленные цели, политики и доказательства оснований задаёт конфигурация установки; из тестов они не выводятся. Публичное размещение, несколько реплик и промышленные учётные данные этим изменением не подтверждаются.

## Следующие шаги до промышленного роста

1. В коде реализованы кандидаты рабочей области, основания помимо согласия, ограничения по цели, уничтожение метаданных/файлов и подтверждение по ID элемента; тесты `9/99`. Промышленные цели, политики, юридические доказательства и копии файлов остаются условиями выпуска.
2. Схема и журнал включены в отдельно формируемые каталог, DBML, покрытие и проверку хешей миграций: [каталог](../database/README.md), [покрытие](../education-database-coverage.md). Основной срез Core/Runtime их не содержит.
3. Настроить постоянное закрытое хранилище и его резервирование вместе с БД. Для реплик выбрать общее хранилище или адаптер `FileStore`, проверить загрузку/скачивание разными репликами и восстановление с SHA-256/размером.
4. Испытать большие списки, расписания, переписку, файлы и лимиты выгрузки. Синхронный ответ Core ограничен 1 МиБ и 1000 записями на секцию; крупная выгрузка требует пока не реализованного отдельного сценария.
