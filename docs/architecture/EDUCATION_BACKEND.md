## Границы и владельцы

Core владеет Account, Person, Organization, членствами, RBAC и аутентификацией. Education использует их публичные прикладные интерфейсы. Предметная область Core не зависит от Education; подключение выполняет корневая сборка зависимостей. Commercial не содержит учебных таблиц и не предоставляет учётные записи Education.

Первый рабочий сценарий — преподаватель. Каждый запрос требует активную учётную запись Core, актуальное разрешение, активное членство в выбранной организации и явное назначение преподавателя Education. Членство и супер-администратор сами по себе не заменяют доменную связь. Группы, ученики, занятия и материалы ограничены организацией и владельцем; диалог доступен только участникам. Адресаты первой версии — назначенные преподаватели той же организации.

| Данные | Владелец и поведение |
| --- | --- |
| Учебный профиль | Education; собственное имя, иначе имя Core Person; аватар необязателен |
| Группы и ученики | Education; ученик выбирается из активного списка людей организации Core |
| Занятия и посещаемость | Education; участники фиксируются при создании, новые зачисления добавляются в будущие занятия |
| Итоги и результаты занятий | Education; один отчёт занятия (тема, пройденное, комментарий) и отдельный результат каждого ученика. Успеваемость не смешивается с посещаемостью, шкала нечисловая и расширяемая |
| Журнал группы и карточка ученика | Проекции сохранённых занятий, посещаемости и результатов; фильтры по периоду и ученику, постранично. Сводка считает только сохранённые статусы, без вымышленных оценок |
| Аккаунты учеников | Education ссылается на Core Account: активация по одноразовому приглашению, отзыв не удаляет учебную историю. Пароли и сессии остаются в Core |
| Активности и попытки | Education; определения, назначения, попытки и типизированные результаты. Завершение попытки идемпотентно, `student_id` никогда не принимается как доказательство личности |
| Расписание и хронология | Проекции реальных занятий и событий, сортировка по моменту времени и ID |
| Требует внимания | Занятия предыдущего локального дня с сохранёнными отсутствиями; пустой список скрывает блок |
| Переписка и уведомления | Education; сообщения двух преподавателей, входящие сообщения и возрастающий указатель прочтения |
| Материалы и аватар | Education; метаданные в БД, закрытый файловый адаптер вне корня веб-сервера |
| Компьютеры и сессии | DeviceManagement (`device_management`); устройства с собственными ключами, одноразовые коды регистрации, строго упорядоченные переходы сессий, одна активная сессия на устройство |
| Документы ученика | Storage (`storage`); версии, манифесты, конфликты и краткоживущие tickets; бинарные данные вне PostgreSQL |

Отсутствие организаций, занятий, материалов и событий имеет своё пустое состояние. Ошибки не превращаются в успешный пустой ответ. Рабочая среда не создаёт демонстрационных данных. Тестовые учётные записи и списки Core создаются только после проверки одноразового окружения.

## HTTP и интерфейс

Семейные связи, приглашения и отдельный родительский scope описаны в [архитектуре родительского кабинета](EDUCATION_PARENT.md). Текущий локальный результат и границы проверки приведены в [EDUCATION_05](../operations/EDUCATION_05_LOCAL.md); исторические числа тестов ниже не являются новым прогоном.

[Контракт OpenAPI Education](../../contracts/openapi/education.yaml), [Homework](../../contracts/openapi/homework.yaml) и [родительского кабинета](../../contracts/openapi/education-parent.yaml) описывают действующие области API. Организация передаётся в `X-Education-Organization`; сервер повторно проверяет доступ. Все личные ответы, включая ошибки авторизации, имеют `Cache-Control: no-store`. Страница коллекции — до 50 записей, диапазон расписания — до 31 локального дня. Границы дня учитывают часовой пояс IANA и переходы летнего времени DST.

Интерфейс включает `/today`, `/calendar`, `/people`, `/devices`, `/groups/:id`, `/groups/:id/journal`, `/groups/:id/activities`, `/students/:id`, `/lessons/:id`, `/lessons/:id/edit`, `/lessons/:id/results`, `/messages`, `/more`, формы создания, детали занятий, посещаемость, материалы и уведомления. Шесть быстрых действий ведут в реальные сценарии. `/lessons/current` явно сообщает об отсутствии текущего занятия. Кабинет ученика `/student/*` объединяет дневник, активности с тренажёром Platform Typing, прогресс и документы; вход — только через Core, активация — по одноразовому приглашению преподавателя. Неделя, выбранная дата и язык берутся из контекста сервера. Нижняя навигация имеет пять пунктов, высоту 72 пикселя плюс безопасную область экрана. Inter хранится локально. Канонический светлый экран: [мобильный макет](../../apps/frontend/design/мобайл.svg), 393×852.

### Правила жизненного цикла

| Сущность | Разрешённые изменения |
| --- | --- |
| Группа | Переименование и изменение состава только до архивации; архив сохраняет группу, состав и историю. Архивирование запрещено, пока есть запланированные занятия. |
| Участник | Добавление идемпотентно и не создаёт дубликат; исключение удаляет только членство в группе, сохраняя Core Person и посещаемость прошедших занятий; перевод атомарно переносит членство и будущие снимки посещаемости. |
| Занятие `scheduled` | Полное редактирование названия, группы, времени и места; перенос и отмена; завершение после начала. Пересечение с другим запланированным занятием владельца запрещено, смежные интервалы и события допустимы. |
| Занятие `completed` | Расписание, группа, название и место только для чтения; посещаемость можно корректировать; материалы можно добавлять, удаление из истории запрещено. Итоги занятия и результат каждого ученика можно сохранять и исправлять; исправление добавляет ревизию, не затирая историю. |
| Занятие `cancelled` | Расписание и посещаемость только для чтения; материалы можно удалить; завершить отменённое занятие нельзя. Итоги и результаты изменять запрещено — `409 lesson_cancelled`. |
| Результат ученика | Строка привязана к занятию и ученику, а не к членству в группе: исключение, перевод и архивация сохраняют историю. Статусы `pending`, `mastered`, `developing`, `needs_support` расширяемы миграцией; числовая шкала не вводится. |

Повторное завершение и повторная отмена идемпотентны. Повторное редактирование завершённого или отменённого занятия с теми же значениями возвращает текущее состояние, а с изменёнными — `409 lesson_locked`. Смена группы занятия допускается только при отсутствии отмеченной посещаемости; иначе возвращается `409 attendance_recorded`. Смена организации, отзыв роли или разрешения, а также чужие ID не раскрывают ресурсы преподавателя.

Материалы: PDF, `text/plain`, PNG, JPEG, WebP, до 10 МиБ. Аватар: только изображения до 2 МиБ и 20 млн пикселей. MIME определяется содержимым. Выдача заново проверяет разрешение, длину и SHA-256. Имя не задаёт путь хранения. Адаптер заменяется через `FileStore`; нескольким репликам нужно общее постоянное хранилище. Удаление материала выполнено как двухфазная операция: байты сначала перемещаются во временное хранилище, затем удаляется строка БД; при ошибке транзакции файл восстанавливается. Материалы завершённого занятия не удаляются обычным действием интерфейса.

История по умолчанию возвращает последнюю страницу сообщений по возрастанию времени. Прочтение передаёт ID последнего действительно показанного сообщения, не отмечая пришедшие позднее. Список обновляется явным действием. При смене пользователя или организации запросы отменяются, интерфейс очищается. Секреты Core находятся в памяти; неопределённый результат записи требует сверки списка перед повтором.

## Установка без автоматической выдачи доступа

По умолчанию `EDUCATION_ENABLED=0`, `VITE_EDUCATION_ENABLED=0`: HTTP-маршруты и страницы отсутствуют. Принятие архитектуры само модуль не включает.

1. Применить обычные миграции Core отдельным подключением владельца. Затем выполнить `php yii education:migrate` тем же подключением миграций. Команда идемпотентна, проверяет SHA-256 применённых файлов и регистрирует выключенный модуль.
2. Повторить [выдачу ролей БД](../../scripts/operations/provision-db-role.sh) с `SCHEMAS=core,platform_runtime,public,education` и прежними раздельными секретами владельца, прикладной и служебной ролей. `education.module_migrations` доступен прикладной роли только для чтения. HTTP не работает от владельца БД.
3. Задать `EDUCATION_ENABLED=1` в Yii, выполнить `composer yii-config-rebuild` и перезапустить среду. Настроить постоянный `EDUCATION_FILE_DIRECTORY` вне корня веб-сервера с записью только для приложения. Общий файл `php.ini` разрешает загрузку 10M и POST 12M; обратный прокси должен допускать тот же размер.
4. Через администрацию Core включить `education`, назначить конкретному Account роль `education.teacher`. Нужны активный Person и членство требуемой организации.
5. Отдельно выполнить `php yii education:teacher:assign --actor <admin-account-uuid> --account <teacher-account-uuid> --organization <organization-uuid>`. Проверяются действующий администратор с `core.rbac.manage` и целевой участник. Массового назначения существующим пользователям нет.
6. Собрать интерфейс с `VITE_EDUCATION_ENABLED=1`, разместить с работающим прокси Core API и открыть `/education/login`. Корневой каталог Commercial `/` сохранён.

Выключение модуля Core немедленно блокирует API. Для полного удаления маршрутов выключить оба флага окружения и пересобрать/перезапустить соответствующие части.

## Проверки и границы выпуска

`tests/Education` и `tests/Foundation` запускаются отдельно через PHPUnit с `EDUCATION_ENABLED=1` на защищённой одноразовой БД. Проверяются область доступа, актуальные разрешения, выключенный модуль, DST, хронология и пустой день, жизненный цикл групп и занятий, пересечения, архивация, реальные файлы, указатель переписки, выгрузка и исправление, итоги и результаты занятий, журнал группы, карточка ученика и сохранение истории при изменении состава, аккаунты и приглашения учеников, активности и тренажёр с идемпотентным завершением, регистрация и сессии устройств, документы и конфликты Storage (29 тестов / 409 утверждений на текущем срезе). `scripts/e2e-education.mjs` проходит реальные вход Core, PostgreSQL и файлы, формы, завершённое скачивание, двух пользователей, русский/английский языки, светлую/тёмную темы, 393×852/1440 и axe. CI выполняет это после существующих браузерных сценариев Core.

Выгрузка, исправление, кандидаты хранения, основания помимо согласия, ограничения по цели и уничтожение подключены через интерфейсы Core. `education.workspace` представляет принадлежащую субъекту рабочую область. Обработчик уничтожения удаляет метаданные и внешние байты в порядке внешних ключей; `education.privacy_receipts(item_id, result)` записывается последним, делая повтор по ID элемента идемпотентным. Юридические запреты и основные блокировки Core остаются определяющими.

Синтетические тесты проверяют кандидатов, основания, ограничения, уничтожение и файлы. Промышленные цели, политики и доказательства оснований задаёт конфигурация установки; из тестов они не выводятся. Публичное размещение, несколько реплик и промышленные учётные данные этим изменением не подтверждаются.

## Следующие шаги до промышленного роста

1. В коде реализованы кандидаты рабочей области, основания помимо согласия, ограничения по цели, уничтожение метаданных/файлов и подтверждение по ID элемента; тесты `29/409`. Промышленные цели, политики, юридические доказательства и копии файлов остаются условиями выпуска.
2. Схема и журнал включены в отдельно формируемые каталог, DBML, покрытие и проверку хешей миграций: [каталог](../database/README.md), [покрытие](../education-database-coverage.md). Основной срез Core/Runtime их не содержит.
3. Настроить постоянное закрытое хранилище и его резервирование вместе с БД. Для реплик выбрать общее хранилище или адаптер `FileStore`, проверить загрузку/скачивание разными репликами и восстановление с SHA-256/размером.
4. Испытать большие списки, расписания, переписку, файлы и лимиты выгрузки. Крупная выгрузка использует потоковый путь Core `exportToStream`; Education contributor по-прежнему ограничивает собственную секцию 1000 записями и отклоняет превышение без частичного результата.

Порядок и критерии: [этапы 2–4 масштабирования](../roadmap/SCALING_PLAN.md). Персональные данные: [поставщики сведений](PRIVACY_MODULE_CONTRIBUTORS.md), [хранение и уничтожение](RETENTION_ERASURE.md). Восстановление: [резервирование](../operations/BACKUP_RESTORE.md).
