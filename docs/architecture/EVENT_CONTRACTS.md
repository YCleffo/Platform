# События между процессами

`contracts/events/envelope.v1.schema.json` задаёт ID события, тип и версию, время, производителя, агрегат, связь с общей цепочкой и причиной, содержимое. Версионированные схемы и валидные тестовые данные существуют для `control_user.email_verification_requested`, `deployment.provision_requested` и `entitlement.issued`.

Изменение обязательной структуры требует новой версии и совместимого потребителя. Тестовые данные проверяются модульным набором Core. Внутреннее событие аудита или исходящей очереди не становится интеграционным контрактом автоматически.

## Доставка

Исходящая очередь Commercial хранит `schema_version`, срок аренды, количество попыток и завершённое состояние или невозможность дальнейшей обработки. Почтовый обработчик обрабатывает зарегистрированные почтовые события. Доставка допускает повторы; потребитель отвечает за дедупликацию по идентичности события. У Core есть входящая очередь с уникальностью `(event_id, consumer)` для поддерживаемых входящих операций.

Универсальный транспорт публикации всех событий между Commercial и Core не реализован. Наличие схемы JSON и таблицы исходящей очереди не означает наличие такого транспорта.

## Документы прав

Выдача новой подписанной версии записывает `entitlement.issued` в той же транзакции. Содержимое включает `entitlement_document_id`, `installation_id`, `document_sha256`. Байты документа, подпись и приватные ключи в исходящую очередь не копируются. Неизменившийся источник не создаёт новую версию и событие.

Core получает документ через аутентифицированное получение M2M и проверяет подпись, доверенный ключ, установку, срок и возрастающую последовательность. Событие исходящей очереди не заменяет получение и проверку документа.

`subscription.activated`, `subscription.cancelled`, `subscription.auto_renew_disabled` — внутренние события Commercial. У них нет потребителя клиентской установки. Права установки сходятся через получение последнего подписанного документа, включая повторную или задержанную синхронизацию.
