# Защита транспорта, браузерная граница и секреты

## Граница браузера и TLS

Platform не шифрует JSON дополнительным самодельным протоколом. Правильная граница выглядит так:

```text
Открытые данные в браузере
    ↓
Шифрование TLS
    ↓
Транспорт HTTPS
    ↓
Завершение TLS
    ↓
Серверное приложение
```

HTTPS защищает содержимое запросов от прослушивания Wi-Fi, посредника без доверенного сертификата,
провайдера, промежуточной сети и стороннего наблюдателя. Он не скрывает данные от владельца браузера
или DevTools. Поэтому запрещены шифрование тел запросов и ответов через JavaScript, обфускация Base64
и собственные «защищённые» протоколы поверх HTTPS.

## Требования к промышленному транспорту

Целевая схема промышленного маршрута:

```text
Интернет
    ↓
HTTPS :443
    ↓
Обратный TLS-прокси / Caddy
    ↓
общая с прокси непубличная сеть caddy_public
    ↓
приложение :80
```

Отдельная промышленная конфигурация развёртывания должна закрывать серверное приложение от прямого
публичного доступа и подключать его только к обратному прокси. `caddy_public` выше —
целевая схема сети, не уже развёрнутая топология. Основной `compose.yaml` предназначен
для локальной разработки и публикует сервисы на локальном интерфейсе; готовой промышленной конфигурации Compose
в репозитории нет. Внутренний HTTP не должен становиться публичной точкой входа.
Внешний Caddy обязан перенаправлять HTTP на HTTPS (оставляя порт 80 только для перенаправления и ACME),
получать и автоматически обновлять валидный сертификат и разрешать только TLS 1.2/1.3.

На промышленном узле Caddy должен добавлять:

```http
Strict-Transport-Security: max-age=31536000; includeSubDomains
```

HSTS не применяется к localhost. Локальная разработка продолжает работать по `http://localhost:8080`.

## Заголовки API и кеширование

Единый промежуточный обработчик добавляет `X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer`,
`X-Frame-Options: DENY` и ограничивающий CSP. Для `/api/auth/*` и `/api/core/*` он также добавляет
`Cache-Control: no-store` и `Pragma: no-cache`. Обработчики запросов не должны дублировать эту политику.

## Ошибки и журналирование

Необработанная ошибка возвращается как локализованная `http.internal_error` без сообщения исключения,
SQL, трассировки, путей или значений окружения. Логгер получает только стабильный код ошибки и тип
исключения, но не объект `Throwable`, его сообщение, аргументы или тело запроса.

Тело запроса по умолчанию не журналируется. Запрещено журналировать `Authorization`, `Cookie`,
`Set-Cookie`, пароли, исходные токены доступа, обновления, активации и сброса, учётные данные SMTP/БД,
контрольную метку безопасности и секрет отпечатка устройства. Будущий журнал HTTP-доступа должен исключать и маскировать чувствительные поля
и ограничиваться ID запроса, методом, именем маршрута, статусом, длительностью, допустимым ID аккаунта,
IP, User-Agent и стандартизированным кодом ошибки.

## Создаваемые материалы

`tests/_output` — локальные временные чувствительные данные. Codeception может сохранять там тело ответа при падении теста, включая одноразовые токены, но каталог исключён из Git, образа Docker и архива проекта.
Исходники тестов, конфигурация Codeception и тестовые данные остаются частью проекта.

## Контракт существующего браузерного клиента

Учётные данные Bearer запрещено хранить в `localStorage`, `sessionStorage`, IndexedDB, постоянных хранилищах Redux/Vue/Pinia, кэше служебного обработчика браузера, URL, строке запроса или фрагменте. Токен доступа при Bearer-аутентификации
может находиться только в оперативной памяти процесса страницы.

Существующая Vue SPA хранит учётные данные доступа и обновления только в памяти, с отдельными
сессиями Core, клиента Commercial и оператора Commercial. Перезагрузка требует входа.
Одноразовый маркер OAuth переносит только несекретный ID клиента и хеш состояния, а не токены.
Для настольных и мобильных клиентов действует API непрозрачных Bearer-токенов и обновления. Сервер-посредник BFF или обновление через HttpOnly
не реализованы и требуют отдельного решения; добавление cookie-аутентификации должно
сопровождаться CSRF-защитой в том же изменении.

Предпочтительная промышленная топология — интерфейс и API одного источника (`https://platform.example.com/`
и `/api/*`). API не выставляет разрешающий произвольные источники CORS, не возвращает `Access-Control-Allow-Origin: *` и не
отражает произвольный заголовок Origin. Разные источники в будущем требуют явного разрешённого списка; учётные данные вместе с произвольным источником запрещены.

`ClientContext` остаётся внутренним объектом и не сериализуется целиком. Владелец аккаунта видит для
своих сессий только сведения интерфейса: ID сессии, признак текущей сессии, браузер, ОС и устройство, IP, приблизительное
местоположение и временные метки. Хеш отпечатка, внутренние сигналы риска, состояние доверенного прокси,
исходные заголовки перенаправления и данные другого аккаунта наружу не выдаются.

## Контекст клиента, доверенный прокси, устройство и GeoIP

Один неизменяемый `ClientContext` вычисляется промежуточным обработчиком один раз и содержит определённый IP,
`User-Agent`, `Accept-Language`, язык, часовой пояс и источник его определения, нормализованные подсказки клиента,
сведения устройства, необязательный ID экземпляра клиента, необязательный HMAC отпечатка устройства, приблизительный GeoIP
и ID запроса. Обработчики запросов не переинтерпретируют заголовки самостоятельно.

Непосредственный адрес соединения авторитетен по умолчанию. `Forwarded` и `X-Forwarded-For` учитываются только при
совпадении непосредственного узла соединения с явным IP или CIDR в `TRUSTED_PROXIES`. Цепочка обходится от
приложения к клиенту и останавливается на первом недоверенном адресе; некорректные значения
игнорируются. Ни JSON запроса, ни недоверенный заголовок прокси не задают IP для проверок безопасности.

Определение устройства локальное, через адаптер: браузер, ОС, общий тип/модель устройства и тип клиента.
Запрещены сбор через холст, звук, шрифты, WebGL или аппаратный серийный номер и другие инвазивные способы снятия отпечатка.
UUID экземпляра клиента не равен серверному ID сессии. Отпечаток устройства — HMAC-SHA-256 по небольшому
набору стабильных нормализованных сигналов без IP, GeoIP, токенов и часового пояса; хранится только бинарный
HMAC и используется как сигнал риска, а не идентичность или доказательство аутентификации.

GeoIP — приблизительное местоположение по IP. Частные, зарезервированные, локальные, неверные адреса и отсутствие базы дают неизвестное местоположение. Адаптер читает локальную базу MaxMind GeoLite2 по конфигурации; бинарная
база не коммитится. Отсутствие базы или ошибка поиска не ломают запрос, внешний HTTP-вызов не требуется.
Redis не является источником истины для сессий или GeoIP.

Срок хранения аудита — политика установки. IP, User-Agent, приблизительное местоположение, ID экземпляра клиента
и HMAC отпечатка устройства относятся к данным безопасности и персональным данным. Пароли, хеши, токены сессии/обновления, секреты TOTP, резервные коды, секреты проверок, учётные данные SMTP и исходные отпечатки не попадают в метаданные аудита или произвольные логи. GeoIP, часовой пояс, заголовки перенаправления и сигналы отпечатка не являются
доказательством компрометации.
