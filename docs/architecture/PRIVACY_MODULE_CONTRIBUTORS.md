# Расширение обработки персональных данных через поставщиков сведений

Модуль — владелец персональных данных — регистрирует категории, цели и политики хранения через внедрение зависимостей установки. Core не импортирует его доменные классы. Коды уникальны; схемы проверяются при создании реестра.

| Интерфейс / регистрация | Обязанность модуля |
| --- | --- |
| `PersonalDataContributor` / `personalDataContributors` | Выгрузить только разрешённые поля субъекта в стабильном порядке и пределах лимитов |
| `PersonalDataCorrectionContributor` / `personalDataCorrectionContributors` | Проверить владение и список полей, вызвать каноническое доменное изменение, вернуть ID и пути изменённых полей |
| `RetentionCandidateContributor` / `retentionCandidateContributors` | Перечислить ресурсы и все применимые цели с временными метками события начала отсчёта |
| `LawfulProcessingBasisContributor` / `lawfulProcessingBasisContributors` | Подтвердить действующее основание; при неизвестном основании сохранить данные |
| `ProcessingRestrictionContributor` / `processingRestrictionContributors` | Повторяемо применить ограничение по ID блока, сохраняя основной блок в Core |
| `PersonalDataErasureHandler` | Выполнить только заявленное действие над собственным типом ресурса и согласовать повтор по ID элемента |

Поставщик сведений не копирует исходное содержимое в аудит, исходящую очередь, запрос или свидетельства исполнения. Исправление участвует в транзакции оркестратора. Внешнее действие уничтожения требует собственной сверки по ID элемента: транзакция Core не охватывает внешнее хранилище.

Доступность операции зависит от реально зарегистрированного пути. Доступ/выгрузка и исправление требуют своих поставщиков. Информация об обработке требует полного покрытия целей и реестра определений; прекращение — кандидатов, исполнителей ограничений и покрытия. Общая операция ограничения недоступна без специального пути исполнения.

Уничтожение проверяется для конкретного субъекта: нужны все кандидаты, политика доказательств и подходящие обработчики. Глобальный флаг без инвентаря субъекта не обещает удаления. Core регистрирует удаление дочерних ресурсов и обезличивание Person/человеческого Account; сторонний модуль не получает реализацию автоматически.

## Education при явном включении

| Поставщик | Код / ресурс | Поведение |
| --- | --- | --- |
| Кандидаты хранения | `education.workspace_retention`, `education.workspace` | Одна область субъекта; кандидат на каждую настроенную цель категории `education`; время начала берётся из реального события |
| Правовое основание | `education.workspace_basis` | Для целей без согласия основание выводится из активного Account Core или членства организации; неизвестность сохраняет данные |
| Ограничение обработки | `education.purpose_restriction` | Заявляет покрытие по цели; основной блок остаётся в Core |
| Уничтожение | `education.workspace_erasure`, действие `delete` | Удаление области в порядке внешних ключей, удаление байтов субъекта, подтверждение `education.privacy_receipts` по ID элемента; юридические запреты проверяет Core |
| Выгрузка / исправление | `education.workspace`, `education.profile_correction` | Зарегистрированы; собственные семейные связи, метаданные приглашений и история включены без кодов и хешей; не заменяют хранение/уничтожение |

Родительские записи входят в тот же workspace lifecycle. `FamilyPrivacy` удаляет приглашения, активации, семейную историю и уведомления до удаления FK-зависимостей; уничтожение данных родителя сохраняет учебную историю его детей. Действующая семейная связь не предоставляет полномочия представителя для операций Core Privacy. Подробнее: [родительский кабинет](EDUCATION_PARENT.md).

Промышленные цели, политики, доказательства оснований и сроки задаются конфигурацией установки. Синтетические тесты не являются её утверждённой политикой.
