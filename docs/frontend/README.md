# Пользовательский интерфейс Platform

Одностраничное приложение SPA на Vue 3, TypeScript со строгой проверкой типов и Vite. Оно использует раздельные API Core и Commercial по [контрактам](../../contracts/openapi/). Токены находятся только в памяти. Постоянно сохраняются тема, язык и оформление; после перезагрузки нужен вход.

Родительский кабинет Education находится в `/parent/*`, активация — `/parent/activate`, выбор нескольких разрешённых ролей — `/education/contexts`. Он использует собственный parent workspace, очищает данные при смене ребёнка или Core-сессии и не предоставляет действий от имени ученика. Существующий Core Account может войти для активации до выдачи роли Education. Контракт и политика данных: [родительский кабинет](../architecture/EDUCATION_PARENT.md); фактические локальные проверки и ограничения визуальной проверки: [EDUCATION_05](../operations/EDUCATION_05_LOCAL.md).

## Границы приложения

| Слой | Ответственность |
| --- | --- |
| `app` | Маршрутизатор, макеты, тема, оформление и сборка |
| `core` | Раздельные сессии Commercial и администрации Core, контекст аккаунта, сборка HTTP-клиентов |
| `modules/commercial` | Вход, начальная настройка, каталог, аккаунт, безопасность, приглашения, расчёты, использование, аналитика, аудит |
| `modules/admin` | Административные страницы Core, кэш/операции по поколению сессии, отдельные страницы входа, восстановления и обратных вызовов |
| `modules/commercial/operator` | Независимая операторская сессия Commercial, персональные данные и финансы |
| `modules/education` | Явно включаемая преподавательская область на Core с отдельной областью доступа и данными |
| `modules/settings` | Оформление, общий макет настроек и примеры компонентов |
| `shared` | HTTP-транспорт и проверки, интерфейс, локализация, форматирование, валидация, локальные ресурсы |

`shared` не импортирует `core`/`modules`; общие компоненты не выполняют HTTP-запросы. `core` не зависит от страниц. Модули используют публичные контракты `core/shared`. Core Account, Control User и Commercial Account — разные учётные записи.

В Yii-модуле Education зарегистрировано 145 HTTP-операций. Из них 101 относятся к основным маршрутам Education, учебным активностям, программам и передачам файлов, 24 к домашним заданиям и их интеграциям, 20 к родительскому кабинету и управлению семейными связями. По умолчанию `VITE_EDUCATION_ENABLED=0`, `EDUCATION_ENABLED=0`. Для защищённых операций действуют проверки прав и контекста соответствующей роли. Подробности в [архитектуре Education](../architecture/EDUCATION_BACKEND.md) и [матрице FRONTEND_06](../audits/FRONTEND_06_API_COVERAGE.md).

## Демонстрационные данные

`scripts/dev/seed-demo-catalog.sh` или `.ps1` Windows публикует Старт, Бизнес, Масштаб, Корпоративный. `scripts/dev/seed-demo-commercial.mjs` создаёт локального пользователя Control Plane и два Commercial Account; нужен явный `DEMO_PASSWORD`, нелокальный `CONTROL_API_URL` запрещён. Инструменты только для локальной/одноразовой среды, не промышленного заполнения.

На экране уже 768 пикселей навигацию дополняет полноэкранное меню с удержанием фокуса, Escape, блокировкой прокрутки, безопасной областью, крупными ссылками, разделами аккаунта, темой/языком и входом/выходом. Переход закрывает меню и возвращает фокус кнопке.

Администрация имеет отдельное хранилище сессии и защиту: `/api/auth/login`, MFA, разрешения `/api/auth/me`. Страницы загружаются по требованию отдельными частями: [консоль](../operations/ADMIN_CONSOLE.md). Кэш и ожидающие запросы привязаны к поколению сессии. Выход или смена пользователя сбрасывает кэш; поздние HTTP-ответы, обновления токена, оформление и диалоги не влияют на новую сессию.

Внешнее восстановление сохраняет хеш состояния, провайдера, назначение, срок и несекретный ID клиента в одноразовом маркере `sessionStorage`. Проверка состояния позволяет восстановить ID для серверной привязки входа/восстановления; маркер и код/состояние URL удаляются. Обычная новая страница получает новый ID. Тестовый OAuth-транспорт включается только в защищённой тестовой среде Core; реальные Google/Telegram требуют отдельных секретов и проверки перенаправлений.

Расчёты восстанавливают профиль, черновые/ожидающие документы, историю и открытую смену из `/accounts/:accountId/billing-state`. Запросы привязаны к сессии, аккаунту и поколению операции. Начальная неоплаченная подписка может не иметь периода: показан прочерк. Отмена автопродления сохраняет доступ до конца периода; немедленная отмена завершает доступ, возврат оформляется отдельно. Результаты: [аудит](../AUDIT.md).

Токен приглашения берётся из `#token=…`, удаляется из URL, хранится в памяти. Токен сброса приходит в `?token=…`, не сохраняется в хранилища и удаляется после успешной смены. Ответы запроса сброса/повторной отправки не раскрывают существование аккаунта. Предпросмотр не меняет данные. Разрешения вычисляются сервером и перепроверяются при изменениях; интерфейс скрывает недоступное.

Поколение сессии и ID запросов отбрасывают старые ответы после выхода/смены аккаунта. 401 вызывает одно общее обновление токена и не более одного повтора. Истечение сессии отличается от временной ошибки сети. Чувствительные изменения требуют MFA/недавнего подтверждения; `useSensitiveAction` повторяет действие после дополнительной проверки.

## Дизайн и локальные ресурсы

Источники: [токены дизайна](../../apps/frontend/design/design-tokens.json), [мобильный SVG](../../apps/frontend/design/мобайл.svg). `generate:tokens` переносит цвета, типографику, отступы/промежутки/скругления/размеры; `theme.css` связывает их с семантическими переменными светлой, тёмной и системной тем.

**Значки.** Выбранные Solar Linear SVG находятся в `src/shared/ui/icons/svg/`. `npm run generate:icons` создаёт небольшой `sprite.svg`; `AppIcon` использует `<use href="local-sprite.svg#symbol">`. Именованные экспорты сохраняют типизированные компоненты и параметры динамических компонентов. Vite выпускает спрайт с хешем имени. Полная коллекция `src/shared/Solar icons/` сохранена для будущих экранов и не входит целиком в сборку. Lucide удалён. `check:icons` обязателен в CI. Значки используют `currentColor`, декоративные скрыты от средств чтения экрана, доступное имя даёт кнопка или ссылка.

Новую пиктограмму выбирают из библиотеки, проверяют SVG 24×24, добавляют в `svg/`, обновляют спрайт и типизированный экспорт. Нельзя загружать всю коллекцию или CDN. Сложная многоцветная иллюстрация хранится отдельно. Основа `<use>`: [MDN](https://developer.mozilla.org/en-US/docs/Web/SVG/Reference/Element/use). Будущее переключение Linear/Bold должно использовать карту вариантов внутри `AppIcon`, сохраняя семантические имена экранов и небольшой спрайт.

**Шрифты.** `fonts.css` подключает локальные Inter variable 100–900 и Space Mono 400/700 в WOFF2. Исходные TTF, статические начертания и Roboto сохранены как библиотека и не импортируются в сборку. Inter основной, Space Mono для кодов/ID. Google Fonts и внешних подключений нет. Поставляются [уведомления](../../apps/frontend/public/third-party-notices.txt) и оригинальные OFL в `public/licenses`.

**Типографика.** `base.css` задаёт основной текст 14/20 пикселей при 100%; `typography.css` — заголовки H1/H2/H3, подписи, легенды, мелкий и моноширинный текст. Широкий экран: 24/32, 20/28, 18/24, насыщенность 600; мобильный: 22/28, 18/24, 16/20. Страница выбирает роль `--type-*`, включая размер, высоту строки, насыщенность и межбуквенный интервал. Нельзя полагаться на стандартные заголовки браузера или задавать только кегль. Подпись отличается от мелких метаданных 12/16; поле L крупнее M — 16/24 против 14/20. Масштаб меняет размер и строку вместе. Создаваемые токены вручную не правятся. Класс/стиль `AppInput` относится к обёртке; атрибуты и обработчики ввода — к самому полю.

## Настройки внешнего вида и анимации

`app/appearance` владеет проверенными настройками и корневыми CSS-переменными. `platform.appearance.v1` содержит только оформление. Изменения применяются сразу, синхронизируются между вкладками, переживают перезагрузку. При запрете хранилища работа продолжается в текущей вкладке с сообщением о невозможности сохранения. Сброс сохраняет язык/тему.

Варианты «Сбалансированный», «Компактный», «Удобное чтение» меняют размеры/отступы, сохраняя эффекты и тему. Отмена хранит до 20 изменений в памяти; непрерывное перетаскивание — одно действие. Сброс общего оформления и отдельного ползунка отменяем. Чужое изменение из другой вкладки сбрасывает старую историю. У ползунков точные шаги и индивидуальный сброс; редкие параметры свёрнуты.

| Настройка | Значения |
| --- | --- |
| Плотность | Компактная, обычная, просторная; коэффициенты 0,85 / 1 / 1,15 |
| Шрифт | 90–140%, размер и высота строки вместе |
| Отступы | 75–125% поверх плотности |
| Кнопки | По горизонтали 8–32, по вертикали 6–16 пикселей; без обрезки фиксированной высотой |
| Скругления | 0–150% |
| Тени | Нет, слабые, обычные, сильные; кольцо фокуса сохраняется |
| Анимации | Вкл./выкл., скорость 0,5–2×, тема 0–600 мс |

Исходный JSON дизайна не меняется: генератор CSS выражает размеры через масштабируемые переменные. Новые компоненты используют их; сенсорные элементы не ниже 44 пикселей.

`shared/styles/appearance.css` задаёт общие длительности `--motion-*-duration`, функции плавности и `--theme-transition`. У компонентов нет собственных цветовых длительностей. View Transitions смешивает старый и новый снимки; вложенные цветовые переходы в это время выключены. Быстрое повторное переключение отменяет прежнее, действует последнее. Без API тема применяется атомарно. Системное уменьшение движения приоритетнее пользовательского включения. Основа: [переходы](https://developer.mozilla.org/en-US/docs/Web/API/Document/startViewTransition), [уменьшение движения](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/At-rules/@media/prefers-reduced-motion).

## Выпадающее и контекстное меню

Общий `shared/ui/menus/AppMenu.vue` не знает HTTP и маршрутов. `MenuItem` задаёт уникальный `id`, текст, необязательные описание/значок/подсказку сочетания, недоступность, состояния выбора, детей и вид элемента/группы/разделителя. `select(item)` передаёт действие владельцу. ID уникальны во всём дереве, подписи выводятся текстом. `searchable` ищет конечные элементы с путём разделов; недоступность родителя наследуется.

`shared/ui/fields/AppDropdown.vue` принимает `options: DropdownOption[]`, `label`, `v-model`, необязательные `id`, `searchable`, `multiple`, `clearable`, `disabled`, `invalid`, `placeholder`. По умолчанию поиск `auto` появляется только при более 8 конечных элементах; `true` или пустой атрибут включает принудительно. Одиночная модель — строка, множественная — массив строк. Родитель открывает раздел; выбирается конечный пункт. Множественный выбор не закрывает меню; очистка сбрасывает модель. Не более двух выбранных меток и `+N` сохраняют одну строку; полный список доступен через `title` и доступное имя. Внешний `<label for>` связан с ID кнопки; обязательный `label` обеспечивает имя и без внешней подписи. Сериализация и серверная проверка остаются вызывающему коду.

```vue
<AppDropdown v-model="language" label="Язык" :options="languages" />
<AppDropdown v-model="selected" label="Разделы" :options="tree" multiple searchable clearable />
<AppContextMenu :items="actions" label="Действия" @select="handleAction">
  <section tabindex="0">Область контекстного меню</section>
</AppContextMenu>
```

На широком экране панели каскадные, у края разворачиваются и ограничиваются экраном. Если цепь не помещается или ширина менее 640 пикселей — один уровень и «Назад». Поиск работает из вложенных уровней без потери фокуса. Enter/пробел выбирают; стрелки вверх/вниз, Home/End перемещают; вправо открывает; влево/Escape возвращают. Escape корня закрывает и возвращает фокус; Tab закрывает и продолжает порядок формы. Недоступный пункт получает фокус, но не активируется. Применяются ARIA menu/menuitemradio/menuitemcheckbox: [поведение WAI-ARIA](https://www.w3.org/WAI/ARIA/apg/patterns/menubar/).

В диалоге меню переносится внутрь области модального окна: первый Escape закрывает меню, второй — диалог. Нажатие снаружи не отбирает фокус у новой цели. Нижний слот предназначен для пояснений списка.

`AppContextMenu` открывается правой кнопкой или Shift+F10/ContextMenu на фокусируемой области. Поля, редактируемый контент, ссылки, кнопки, выделенный текст, Shift+правая кнопка и `data-native-context` сохраняют браузерное меню. `SiteContextMenu.vue` добавляет переходы, тему и плотность. Четыре прежних стандартных списка заменены: язык, тени, роли участника и приглашения. Без поиска фокус получает выбранный пункт; стрелки на кнопке открывают первый/последний. Очистка поиска сохраняет фокус поля. Нажатие внешней подписи переключает меню один раз, не закрывая и не открывая повторно.

## Проверки и запуск

Команды: [руководство приложения](../../apps/frontend/README.md). Прокси Vite направляет `/api/control` в Commercial, `/api` в Core. Адреса задают `VITE_COMMERCIAL_PROXY_TARGET`, `VITE_CORE_PROXY_TARGET`, а не компоненты.

Vitest проверяет модули/компоненты без БД. `verify-responsive.mjs` проверяет публичные страницы и состояния защиты на 320–1440 пикселях, темы, клавиатуру, русский язык и переполнение; это не подтверждение авторизованных сценариев. `verify-appearance.mjs` проверяет переменные, хранение, уменьшение движения, тему и размеры; `verify-menus.mjs` — поиск, фокус/клавиатуру, каскады, мобильное возвращение, края, модальность и контекстное меню. Оформление проверяется в предпросмотре промышленной сборки: инструменты отладочной сборки сами используют localStorage и мешают проверке полного запрета хранения. `check:styles` запрещает неопределённые CSS-переменные, собственные длительности и переходы без общей цветовой части. Всё включено в CI.

`npm run verify:typography` проверяет вычисленные размер, высоту строки, насыщенность, семейство и переполнение именованных маршрутов основной SPA: 320–1440 пикселей, текст 100/140%, русский/английский, обе темы. Список сверяется с синтаксическим деревом маршрутизатора. Безопасные HTTP-подстановки содержат заполненные, пустые и ошибочные состояния: это стили, не серверный жизненный цикл. Числа маршрутов/состояний определяет отчёт запуска; у Education отдельная матрица `test:e2e:education`. Снимки и JSON находятся в исключённом из Git `screenshots/`.

`verify-ux.mjs` проверяет отмену, варианты оформления, точные шаги и 30 циклов меню с 10 диалогами; глобальные обработчики должны вернуться к исходному числу. Полный цикл Playwright включает автоматизацию и не равен задержке ввода. `verify-accessibility.mjs` использует axe-core для публичных страниц, входа, настроек, каскадов, модальных/мобильных состояний в обеих темах без исключения A/AA. Авторизованные страницы, включая QR MFA, проверяются в сквозных тестах. Это дополняет клавиатуру и снимки, но не доказывает полное соответствие WCAG: [границы автоматизации](https://playwright.dev/docs/accessibility-testing).

`load-commercial.mjs` до создания тестовых данных проверяет одноразовое окружение. Профили описаны в руководстве приложения. Чередуются четыре GET с проверкой JSON: опубликованный каталог трёх синтетических тарифов/цен/возможностей, текущий пользователь, непустые аккаунты и активная сессия. Запросы одной сессии; параллелизм ограничен профилем. Транспортные, статусные и контрактные ошибки считаются отдельно; автоматических повторов нет. Пустой или слишком короткий этап не проходит. CI использует короткий профиль, локально доступны обычный и стрессовый. Перенос на промышленную среду требует представительных данных, окружения и согласованных SLO.

Полная браузерная задача поднимает отдельные PostgreSQL/Commercial/Mailpit, исходящий обработчик, Vite и Chromium. `e2e-account-workspace.mjs` и `e2e-invitation-lifecycle.mjs` проходят аккаунт, расчёты, использование, аналитику, аудит, выгрузку, приглашения/MFA/членства. Авторизованная матрица доступности включает центр безопасности, настройку MFA, резервные коды и проверку MFA. Мобильное полноэкранное меню на 393 пикселях проверяется на размеры, блокировку прокрутки, Escape, возврат фокуса и закрытие после перехода.

`e2e-auth-recovery.mjs` проверяет самостоятельную повторную отправку после перезагрузки, замену токена подтверждения, реальное письмо сброса, новую вкладку, одноразовость, неверный/отсутствующий токен и чистоту URL. Защитная проверка требует подтверждённое сервером случайное значение изоляции. Перед восстановлением и нагрузкой CI сбрасывает одноразовую схему Commercial, чтобы прежние приглашения не исчерпали лимиты и не дали 429.

Прокси использует `http.Agent({ keepAlive: false })` без `Connection: close`, вызывавшего ECONNRESET на быстром Core. Транспортная ошибка прокси даёт 502; клиент повторяет **один идемпотентный GET** после сетевой ошибки/502. Серверные 5xx и POST не повторяются. Рабочие БД не используются; после задачи ресурсы удаляются.

### Флажки, переключатели и диапазоны

`AppCheckbox`, `AppSwitch` из `shared/ui/fields` принимают логический `v-model`, обязательные `id`/`label`, описание, недоступность и имя. Флажок также поддерживает `indeterminate`, `required`, `value`. Это реальные HTML-поля с пробелом/Tab, нажатием подписи, недоступностью и участием в форме. Промежуточное состояние управляется отдельно. Подсказка объединяется с `aria-describedby`, имя берётся из подписи.

`AppSortableList` — список строк `v-model: string[]`, ручка перетаскивания, стандартное HTML5-перетаскивание, клавиатурные Alt+стрелки вверх/вниз и доступная подпись позиции. `AppInput`, `AppCheckbox`, `AppSwitch` передают `name`, `form`, `required`, `autocomplete` реальному элементу, не обёртке. Обычный `form.reset()` после события синхронизирует модель с DOM; `@reset.prevent` сохраняет элемент, модель и `FormData`. Недоступные элементы не отправляются.

Переключатель меняет настройку немедленно, флажок выбирает пункт. Общий/частичный выбор и недоступность показаны в `/settings/components`; флажок есть и в живом предпросмотре.

`AppRange` сохраняет стандартные мышь, касания и клавиатуру. Дорожка обновляется без задержки, бегунок растёт при удержании. Отпускание снаружи, отмена касания, потеря фокуса и отключение завершают изменение. Перетаскивание — одно действие отмены. Цвета используют `--theme-transition`, геометрия — `--motion-control-duration` и `--motion-spring-ease`; скорость и уменьшение движения наследуются.

`BASE_URL=http://127.0.0.1:5173 npm run verify:controls` выполняет 30 браузерных утверждений: мышь/касания/клавиатура, частичный выбор/недоступность, атрибуты и сброс форм, отменённый сброс, отпускание снаружи, отмена изменений, перезагрузка, уменьшение движения и 320 пикселей при тексте 140%. Скрипт включён в CI; снимки — `screenshots/`. История и текущие результаты разделены в [аудите](../AUDIT.md).

### Собственные настройки и согласия Core

`/admin/profile`, `/admin/profile/consents` внутри `CoreProfileLayout` доступны любой сессии Core без управления чужими аккаунтами. Типизированный адаптер `shared/api/core/account.ts`, контракт `contracts/openapi/account-settings.yaml`. PATCH предпочтений передаёт только изменённые язык/пояс; пропущенное сохраняется атомарно. Схема 2 хранит разреженные переопределения; null сбрасывает известное конечное поле. Форма не отправляет пространства модулей и не удаляет чужие настройки.

`core/admin/accountSettingsStore.ts` хранит данные в памяти, синхронно сбрасывается по поколению сессии и отклоняет позднее. `AdminLayout` применяет сохранённые анимацию/прозрачность через API оформления; выход возвращает браузерные настройки. Уменьшение движения пользователя/ОС приоритетно. Переключатели формы действуют после сохранения. Флаги уведомлений сохраняют каналы, не запрашивая разрешение браузера.

Заголовок/текст согласия обычные, связаны сервером с SHA256. POST передаёт просмотренные версию/хеш; 409 требует повторного чтения. Необязательный документ без текста и пустой реестр показывают заменяемые русские/английские шаблоны `modules/admin/profile/consentTemplates.ts`; их просмотр не создаёт ложное согласие. Опубликованный документ требует явно неотмеченного флажка и подтверждения; отзыв — отдельного диалога с повторной попыткой. Реестр задаётся конфигурацией Core.

`verify:core-profile` — HTTP-подстановки, адаптивность/axe. `test:e2e:core-profile` — настоящий одноразовый Core/PostgreSQL/Redis, постоянное состояние, выход/вход и конкурентные PATCH.

### Ключи доступа и внешние аккаунты Core

`AdminPasskeysView`, `AdminIdentitiesView` находятся во вкладках `/admin/security` для любой Core-сессии. DTO/методы: `shared/api/core/credentials.ts`; браузерная граница: `shared/webauthn.ts`. Параметры WebAuthn переводятся из base64url в ArrayBuffer, подтверждения обратно в JSON. Требования UV и хранимого у аутентификатора ключа не ослабляются. Сериализация/отмена соответствуют [WebAuthn Level 3](https://www.w3.org/TR/webauthn-3/). Сервер проверяет RP/источник, проверочный запрос, сессию/клиента, подпись и счётчик; закрытый ключ остаётся у аутентификатора.

Вход через ключ использует `adminAuthStore.accept`: обязательные MFA/смена пароля продолжаются теми же формами. Системный запрос получает AbortSignal текущей операции; выход, отмена, уход и новая попытка отвергают поздний ответ. Создание/удаление требуют недавнего подтверждения. Конфликт последнего способа 409 не превращается в успешное удаление. Переименование допускает метку null; форма — до 160 символов.

`auth/externalLink.ts` открывает окно сразу по нажатию, обнуляет `opener`, пишет одноразовый OAuth-маркер в его `sessionStorage`: хеш состояния, провайдер, срок, назначение, ID клиента. Токены и код в хранилище сессии Core не попадают. Обратный вызов очищает URL, потребляет маркер и передаёт код через BroadcastChannel с именем из SHA256 состояния.

Окно не восстанавливает ID исходной вкладки: завершение привязки под её собственной Core-сессией вызывает сама вкладка, принимая только совпадающие провайдер/состояние. Отмена, удаление компонента или смена поколения закрывают канал/окно; поздний вызов не меняет данные. Учтены блокировка окон, тайм-аут, отмена провайдера, конфликт владельца, неполное обнаружение и последняя внешняя запись. Замена токенов в той же сессии поддерживается.

На узком экране вкладки прокручиваются горизонтально; активная остаётся видимой без скачка страницы. Формы используют общие диалоги/кнопки/поля и CSS-токены. Сообщения русского/английского меняются реактивно. CI включает `verify:core-credentials` с подстановками/axe/адаптивностью/виртуальным аутентификатором и `test:e2e:core-credentials` с защищённым реальным сервером, виртуальным аутентификатором, синтетическим OIDC, проверками PostgreSQL, новым входом и 100 конкурентными авторизованными чтениями.

## Самообслуживание персональных данных Core

`/admin/profile/privacy`, `/admin/profile/privacy/:id` доступны человеческому аккаунту без операторских прав. [Адаптер](../../apps/frontend/src/shared/api/core/privacy.ts) проверяет DTO, восемь типов запросов, собственный/представительский путь. [Хранилище](../../apps/frontend/src/core/admin/privacyRequestsStore.ts) держит только метаданные, по 25 строк и служебную строку наличия продолжения. Поколения сессии/запроса отбрасывают позднее; ошибка следующей страницы сохраняет строки и смещение повтора.

Форма выбирает себя или доступное подтверждённое полномочие. Сервер отдаёт только проверенные действующие неотозванные полномочия с нужными действиями; доказательства, ссылки и глобальный поиск людей не раскрываются. Типы зависят от полномочий; уничтожение/прекращение требуют подтверждения. POST не повторяется автоматически: при неопределённости сначала сверяется список. Право только подачи подтверждает приём без обещания просмотра.

Статусы, сроки и просрочка серверные. Выдача данных/информации об обработке — только `in_progress`, с перепроверкой полномочия и завершением запроса. Это одноразовый изменяющий состояние GET: `coreAdminHttp.document` сохраняет исходный текст и запрещает повтор после временной ошибки. Обновление токена при 401 общее. Метаданные/POST ждут 15 секунд, выдача 60; тайм-аут не создаёт второй запрос. Подсказка доступа не показывает отказ до завершения загрузки.

`AppJsonResponseDialog` сохраняет прежних потребителей, принимает необязательные описание/слот действий. Предпросмотр форматируется, скачивание использует точные байты. Субъект/схема проверяются до показа. Документ только в памяти компонента, остаётся при ошибке обновления метаданных, удаляется при уходе/выходе. Blob URL освобождается. Перезагрузка завершённого запроса не обещает новую копию.

`verify:core-privacy` проверяет подстановки, адаптивность/axe, права, ошибки, повторы, неопределённость и тайм-ауты. `test:e2e:core-privacy` — реальный защищённый Core/PostgreSQL/Redis, четыре собственные/представительские выдачи, SHA256/размер БД, отзыв полномочия, изоляция и пагинация/нагрузка. Только раскрываемые сведения оператора синтетические: `CORE_PRIVACY_BROWSER_FIXTURE=1` требует тестовое окружение, отдельные БД/Redis и доказательство изоляции; небезопасное запрещено. Промышленные организация, адрес и цели настраиваются отдельно; неполнота блокирует. [Контракт](../../contracts/openapi/core-privacy.yaml).

## Операторские запросы персональных данных и присутствие

`AdminPrivacyView` использует типизированный `PrivacyOperatorRequests` вместо общей таблицы. Вкладки запретов уничтожения и дополнительных действий типизированы. Сервер фильтрует статус, тип, просрочку и страницы по 25, а не только загруженные данные. Позднее отбрасывается; ошибка продолжения сохраняет прежнее. Чтение и управление раздельны; люди/контакты отдельно требуют `core.persons.read`, полного непостраничного запроса нет.

[Адаптер оператора](../../apps/frontend/src/shared/api/core/privacyOperator.ts) сохраняет реальные camelCase-поля запроса и snake_case-поля блока. `requests/options` отдаёт только коды целей. Исправление человека связано с субъектом запроса; контакт и ограничение ресурса — только с его контактами. Несколько полей отправляются вместе; null/логическое значение не превращаются в пустую строку. Внекабинетные запросы требуют настоящей проверки личности и существующих ссылок доказательств. ISO-даты браузера нормализуются до секунд, иначе 422.

Ручного перехода в конечный статус нет. Подтверждение запускает срок исправления; исправление, выдача и прекращение завершаются серверными сервисами исполнения. Продление одно, рассчитывается сервером. Снятие касается выбранной записи. Прекращение допускает частичный исход или отказ из-за неполных реестров; данные не удаляются, отказ не подменяется успехом.

DTO имеет допускающий null `intakeChannel`; операторская выдача только для офлайн-поступления. Без поля во время постепенного обновления кнопка скрыта. Yii `Route::defaults` превращает скаляры в строки: прежнее `operator === true` не работало. Применяется серверный строковый режим `intake` с сохранёнными правами и проверками субъекта/канала. Предпросмотр/скачивание используют исходную передачу, одноразовость без повтора и время жизни сессии как самообслуживание.

[Хранилище присутствия](../../apps/frontend/src/core/admin/presenceStore.ts) делает POST раз в 30 секунд только при сохранённом `show_online_status=true` и активной человеческой Core-сессии. Скрытие, отсутствие сети, удаление компонента, отказ от настройки или смена сессии отменяют запрос/таймер; поздний результат не меняет новую сессию. Тайм-аут 10 секунд, задержки ошибок 60/120; параллельных сигналов нет. Присутствие и неизвестность различаются; серверный TTL 90 секунд. Временный `X-Client-Instance-ID` передаётся при сигнале и выходе, чтобы удалить только свою запись. Он только в памяти страницы. `PresenceVisibilityPolicy` и отношения модулей проверяют видимость.

В TLS-разработке/предпросмотре Vite согласует HTTP/1.1 через ALPNCallback, устраняя воспроизведённые зависания HTTP/2 с локальным прокси. Сертификаты не ослабляются; исключение самоподписанного ограничено контекстами тестов. Обычный сквозной браузерный тест не отключает HTTP/2 флагом Chromium. Основа: [Node TLS ALPNCallback](https://nodejs.org/api/tls.html#tlscreateserveroptions-secureconnectionlistener).

## Конфигурация Core: модули, значения и публикация

`/admin/modules` — список/карточка, подтверждённые включение/отключение. `/admin/settings` — системные настройки, флаги и текущая публичная конфигурация. До изменения/удаления читается конкретный ключ/код. Адаптер `src/shared/api/core/configuration.ts`, [контракт](../../contracts/openapi/core-configuration.yaml) на 17 операций.

`ConfigValueEditor` редактирует скаляры/объекты/списки рекурсивными полями, без текстового редактора JSON. Сохраняются false/0/null, проверяются числа, имена/дубли свойств, лимит 16 КБ. У модульных настроек нет isPublic. Публикация требует отдельного подтверждения. Публичный предпросмотр читает анонимный API без cookie/Bearer и не применяет произвольные ключи приложению. Похожие на секреты ключи запрещены сервером и адаптером.

Флаги используют поиск модуля, переключатель, диапазон 0..100 и редактор объекта. Без права чтения список не вызывается, связь сохраняется. Интерфейс показывает конфигурацию; фактическую доступность считает сервер. Бизнес-схемы значений API пока не раскрывает; версия — метаданные.

`useConfigCollection` разделяет записи/формы по времени жизни и поколению Core-сессии. 403 очищает; 503 сохраняет строки, запрещая изменение до обновления. Неопределённая запись не повторяется: нужен просмотр списка даже после закрытия диалога. Права чтения/управления раздельны.

`verify-core-configuration.mjs` проверяет HTTP-подстановки, адаптивность/axe, языки, чтение и неопределённую запись. `e2e-core-configuration.mjs` — одноразовый Core/PostgreSQL/Redis, операторская MFA, 17 операций интерфейса/API, проверки БД и короткая серия чтений. Оба в CI.

## Справочники Core и оператор Commercial

`modules/admin/workbench/catalog.ts` описывает 57 операций и ресурсов конкретными полями/запросами: организации, люди, аккаунты, контакты, сервисные данные, RBAC/аудит, персональные данные и реестр приватности. `TypedFields`/`EntityPicker` используют доступные справочники и явную пагинацию. Поиск только по загруженному, кнопка получает следующую страницу. Без права чтения запрос не выполняется; оператору только записи остаётся точная ссылка/код. Неизвестные ID и внешние документы не заменяются выдуманными вариантами. Четыре API рабочих списков персональных данных возвращают только ID/имя/статус; распространение ограничено собой или разрешениями текущего аккаунта. Основные действия учитывают статус; сервер перепроверяет права/правила. Неопределённая запись не повторяется.

`/operator` использует отдельную сессию в памяти на существующем механизме Commercial. Чужие клиентские/Core токены, cookie и хранилища не заимствуются. `/operator/me` проверяет настоящие записи полномочий персональных данных, финансов и каталога; владение клиентом их не заменяет. `/operator/catalog` требует `commercial.catalog_operators`: черновики/новые версии редактируются, опубликованные условия неизменяемы.

Чтение и изменение проверяют полномочия при каждом вызове. Финансы требуют недавней MFA и второго оператора; проверка доказательств сохраняет неизменяемые ссылки/хеши. Дополнительная проверка проходит внутри открытой формы, повтор отправки явный. Автоматической выдачи прав рабочим аккаунтам нет. Прямое добавление членства существующего активного пользователя — отдельная подтверждаемая форма; нового человека приглашают.

`npm run verify:workflows` проверяет подстановки и 63 прежних разрыва интерфейса, не реального платёжного провайдера. `npm run test:workbench-contracts` сверяет методы, пути и права маршрутов PHP Core. Реальные наборы, готовность и снимки: [аудит](../AUDIT.md).

Периодические расчёты проходят отдельную браузерную приёмку с настоящими планировщиком, HTTP/PostgreSQL/SMTP/MFA и синтетическим внешним транспортом. Только `compose.billing-clock.yaml` подключает тестовые образы времени: общий для PHP/PostgreSQL файл смещения только для чтения, консоль использует ту же защищённую точку входа. Промышленная среда, чужая БД, отсутствие изоляции/случайного доказательства блокируют их запуск. Обычные промышленные Compose/Dockerfile не подключают смещение и не дают HTTP API времени.

Перед скачком тест приостанавливает свои два контейнера, меняет файл, возобновляет. Время узла и монотонные таймеры реальны. Это не доказывает реальное прохождение месяца: libfaketime перехватывает календарное время, а не все внутренние таймеры PostgreSQL/Go. [Описание libfaketime](https://github.com/wolfcw/libfaketime).
