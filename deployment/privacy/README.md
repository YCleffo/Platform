# Конфигурационный документ персональных данных установки

Поместите проверенный промышленный JSON в `deployment/privacy/deployment.json`. Docker Compose подключает каталог только для чтения в `/run/privacy`; `PRIVACY_CONFIG_FILE` указывает на файл. JSON исключён из Git: он может содержать ссылки на доказательства и HMAC-ключ свидетельств уничтожения.

Используйте `docs/privacy-deployment.example.json` как исходное описание структуры. Заполните все определения и разделы доказательств из утверждённых документов оператора, договоров, календаря и решений о сроках хранения. Пустые списки и незаполненные доказательства намеренно оставляют проверку промышленной готовности в `FAIL` — «ошибка». `apps/backend/tests/Fixtures/privacy/synthetic-production-policy.json` — синтетические данные CI только для проверки загрузчика; это не шаблон политики и не промышленное доказательство. Не переносите пример или тестовый файл в промышленную среду как готовую политику.

Календарь рабочих дней должен покрывать сегодня и как минимум следующие 31 день, содержать проверенную ссылку на источник и время проверки; его нужно обновить до окончания покрытия.

Ключи строк определений JSON совпадают с именами параметров PHP-конструкторов соответствующих классов `*Definition`. Даты `activeFrom`, `activeUntil`, `notificationSubmittedAt`, `regulatorReviewUntil` содержат смещение часового пояса. Неизвестные поля и неразрешённые ссылки на цели отклоняются. Версия документа согласия на распространение и SHA-256 задаются здесь и не принимаются от API-клиентов. Развёрнутый файл включает все разделы шаблона.

`privacyDestructionEvidence.hmacKey` передаётся как секрет; срок хранения свидетельств должен быть проверен на период не менее трёх лет. `privacyLegalEvidence` фиксирует имя/код системы и способ уничтожения, а при необходимости — имя и адрес обработчика.

До использования `/api/control/privacy/operator/requests/intake`, `/requests/{id}/resolve` и `/incidents` добавьте в `commercial.privacy_operators` уполномоченного Control User и ссылку на основание полномочий. Тело запроса связывает проверенного субъекта без пользовательской записи с ID платёжного профиля, счёта или чека и сохраняет URN внешнего доказательства личности. Исправление или уничтожение изменяемых платёжных контактов не меняет финансовые снимки.

Для установленного лица без прямой связи с записью, `subjectKind: "other"`, ответ о доступе или информации об обработке требует `responseEvidenceReference` на проверенный внешний документ ответа.

При включении необязательного Education корневая сборка зависимостей регистрирует его поставщиков сведений о хранении и основаниях, ограничений и обработчик уничтожения. Утверждённая политика всё равно должна задавать цели `education`, правила и доказательства; модуль не выводит промышленные сроки автоматически. Байты файлов Education требуют собственной процедуры резервирования и повторного уничтожения после восстановления вместе со снимком БД.

Задайте `CONTROL_PRIVACY_OPERATOR_NOTIFICATION` как проверенный JSON-объект. Если уведомление обязательно, включите `required: true`, `status: "submitted"`, `number`, `date`, `evidence_reference`, `registered_purposes`, `database_location_reference`. При проверенном исключении укажите `required: false` и `exemption_reference`. Запустите `php bin/console control:privacy:check` в установке Control Plane, чтобы увидеть недостающие доказательства. Проверка Core отдельно сообщает об отсутствии календаря, сведений оператора, уведомления РКН, безопасности, резидентности и свидетельств уничтожения.
